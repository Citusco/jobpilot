# Implementation Plan: NestJS + Prisma API Migration

**Branch**: `scrum-38-nestjs-prisma-migration` | **Date**: 2026-08-02 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-nestjs-prisma-migration/spec.md`

## Summary

Replace the current (unimplemented-beyond-scaffolding) Fastify + Drizzle foundation with
NestJS + Prisma, per constitution v2.0.0 Principle IV. Concretely: a NestJS application
bootable via the existing `npm run dev` workflow with a `/health` endpoint; the two
existing data entities (`JdSubmission`, `CandidateTrainingDirection`, from SCRUM-3)
re-expressed as an equivalent Prisma schema and migration with pgvector enabled for the
first time; Fastify/Drizzle dependencies and code fully removed; typecheck/lint/test all
green. No business endpoints are implemented in this feature (see spec.md Assumptions).

## Technical Context

**Language/Version**: TypeScript (Node.js >=20, ESM — `"type": "module"` in package.json,
`moduleResolution: NodeNext`)

**Primary Dependencies**: `@nestjs/core`, `@nestjs/common`, `@nestjs/platform-express`,
`reflect-metadata` (NestJS peer dependency), `prisma` (dev) + `@prisma/client` (runtime),
`zod` (existing — reused for the health-check response shape, see research.md §3)

**Storage**: PostgreSQL with the `pgvector` extension, managed via Prisma migrations
(`prisma/schema.prisma`, `prisma/migrations/`)

**Testing**: Jest with `ts-jest`'s ESM preset (existing `jest.config.ts`, unchanged) +
`@nestjs/testing` for module-level tests

**Target Platform**: Linux server (Node.js backend service)

**Project Type**: Single backend web service (this is the API/persistence side only; the
agent orchestration service is a separate Python codebase covered by a different feature)

**Performance Goals**: None beyond SC-001 (health check responds within 10s of service
start) — no other performance requirement in scope

**Constraints**: Zero Fastify/Drizzle references may remain anywhere in the codebase or
dependency manifest on completion (FR-006); the two existing entities' fields, types, and
constraints must be preserved exactly (FR-003)

**Scale/Scope**: 2 persisted entities, 1 HTTP endpoint (health check); foundation only —
no business endpoints in this feature

No `NEEDS CLARIFICATION` markers remain — all open questions were resolved with reasonable
defaults, documented either in spec.md's Assumptions or research.md's decisions.
