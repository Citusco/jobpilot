# Structure probe

Stats only — no section-splitting, no cross-source taxonomy, no ingestion. Generated by `corpus/tools/structure_probe.py` over exactly the file set each source's manifest ended up with (`.md`/`.mdx` for git sources; raw, unconverted `.html` for web sources — headings there come from real `<h2>` tags, not markdown syntax).

**Caveat on HTML sources (msio, fowler, anthropic, aws-wa's `.html` pages, sre):** raw HTML includes page chrome — nav bars, footers, "related articles", author bios, social-share widgets — which git sources never have (those are clean content-only `.md` files with no site wrapper). A `<h2>` in a footer counts the same as a `<h2>` in the article body here. Concretely: fowler's `form: structured` call below is driven by `Thoughtworks`/`about me`/`Topics`/`follow` — Fowler's site-wide sidebar, present on all ~900 pages — not by any real content template. Don't trust an HTML source's `structured` verdict without opening its top-headings table and checking whether the qualifying headings are actually content sections.

"structured" vs "prose" heuristic: a source is called **structured** if at least 2 distinct H2 headings each appear in at least 30% of that source's files (i.e. there's a recognizable fixed template — Benefits/Drawbacks/When to use and similar). Otherwise **prose** — tradeoffs are presumably embedded in running text with no dedicated section, so this cutoff finding it there is coincidence, not template.
